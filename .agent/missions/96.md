# Mission 96 — API documentation generation.

Goal: API reference docs for `src/ine/` generate into `docs/api/` (pdoc —
Sphinx is rejected, see step 1), every public function carries a docstring,
and a docstring-coverage check runs in the suite.

Files:
  - docs/api/                       (generated output)
  - pyproject.toml                  (edit: optional docs dependency/extras)
  - src/ine/*.py                    (edit only where docstrings are missing)
  - tests/test_api_docs.py          (new)

Steps:
  1. [ ] Decide the generator now: use **pdoc** (pure-Python, reads
          docstrings, no conf.py, renders to static HTML). Sphinx is
          rejected for this repo's size (setup cost, theme, autodoc
          annotations). Record the choice in the README of docs/api.
  2. [ ] Audit `src/ine/*.py` public surface: `lexer`, `parser`, `semantic`,
          `interpreter`, `dictionary`, `autocomplete`, `backend_html`,
          `backend_visual`, `backend_c`, `native`, `cli` (each module's
          public functions and classes). Add missing module/function
          docstrings where a public symbol lacks one (one-line is enough);
          do NOT restructure code or export anything new.
  3. [ ] Add `src/ine/formatter.py` coverage only if it already exists
          (item 85) — otherwise list it as an expected addition, not a
          failure.
  4. [ ] Add `tests/test_api_docs.py`: import every public module, and for
          each `def`/`class` not starting with `_`, assert it has a non-empty
          docstring (or is a re-export). This is the "docstring consistency
          check". Keep it tolerant of intentional one-liners and property
          getters/setters.
  5. [ ] Add an optional dev extra to pyproject.toml
          (`[project.optional-dependencies] docs = ["pdoc"]`) and a
          documented command to render: `python -m pdoc -o docs/api
          --html --force ine` (or the pdoc CLI form) run from `src/`.
          Generate `docs/api/` once and commit it (it is the durable
          artifact; regeneration is documented, not CI-enforced).

Verify: `python -m pytest tests/test_api_docs.py -q` passes; the pdoc render
command completes (if pdoc is installed; if not, the test suite still passes
and the command is documented as needing `pip install -e .[docs]`).
Done when: docs/api exists with the module pages, the docstring check is a
paid test, and the render command + dependency are documented.
Do not: add Sphinx config; change public APIs or signatures; wire docs into
CI (documented command only).
