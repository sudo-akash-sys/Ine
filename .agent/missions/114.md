# Mission 114 — Internationalization research.

Goal: a NOTES proposal for multilingual Ine programs — text externalization
(separate `.json` files, `text-key` property), dictionary-kind translation
(French `carte` → English `card`), and locale-aware formatting — research
only, no code.

Files:
  - .agent/NOTES.md           (append one section)
  - src/ine/dictionary.py     (read only)
  - src/ine/semantic.py, interpreter.py  (read only)
  - src/ine/backend_html.py   (read only)

Steps:
  1. [ ] Find where human-visible text lives today: `text`/`title` property
          values (concept "universal" per STATE.md) carried on the Model and
          emitted by backend_html/render for displayed content; `say` output
          via interpreter. Write down that today a program's author writes
          the final language inline — there is no indirection layer.
  2. [ ] Design the externalization in NOTES:
          - **Minimal shape**: a `locale` block or per-program declaration
            pairing a `text-key` property with a sidecar JSON
            (`<name>.i18n.json` mapping key → per-locale strings), resolved
            by one locale at build time (`ine <file>.ine --locale fr`).
            Staying string-replacement keeps backend_html untouched except
            one substitution point; `say` keys resolve the same way.
          - **Dictionary translation**: kinds are already data in JSON — a
            translation is a new `names`/`labels` per-locale field, NOT new
            kind files; `suggest`/completion show the active locale's label.
            The French `carte`→`card` example is an alias-vs-locale question:
            aliases are identity, locale labels are display — do NOT blur
            them (a `carte` feeding you French completions while English
            programs break containment; record the pitfall).
          - **Locale-aware formatting**: numeric/date (typo-proof: there are
            no typed numbers beyond ambient `length` today — flag formatting
            as premature until typed values (WORKBOOK §) land).
  3. [ ] Write NOTES `## Mission 114 — internationalization` with the
          externalization shape, the sidecar JSON schema (concrete example
          for `hello.ine`: key → {en, fr}), the locale flag sketch, the
          alias-vs-locale pitfall, the formatting non-goal, and the
          recommended order (1: `text-key` + sidecar; 2: dictionary locale
          labels; 3: revisit formatting with typed values).
  4. [ ] Verify the sidecar concept against the real pipeline: trace one
          `text` value from `card.json` through semantic.py to an emitted
          html span and identify the ONE substitution point a key-resolver
          would be plugged into. Cite the file:line in the proposal.
  5. [ ] No source change. Any `.tmp/` sketch is scratch and not cited as
          durable.

Verify: `git status` shows no src/ change; the substitution point in step 4
is a real line in the codebase.
Done when: NOTES carries the externalization schema, the alias-vs-locale
