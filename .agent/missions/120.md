# Mission 120 - related compact mission memory

Area: ine-agent
Depends on: 119
Goal: give each mission a small, durable, provider-neutral memory of what the
previous mission did, and load only the snippets that are actually related to
the mission at hand.

## Why

Mission indexes record plans, not outcomes. Without an outcome record, the
next worker in the same area either re-reads the whole history or starts from
nothing. Injecting the full history is what mission 119 removed, so the
replacement must be a bounded, selective read rather than a smaller dump.

## Files

- `src/ine_agent/compaction.py` (new) - write and select compact snippets.
- `src/ine_agent/supervisor.py` - include the selection in the prompt.
- `src/ine_agent/state.py` - index metadata parsing (`Area`, `Depends on`,
  `Files`).
- `tests/test_ine_agent.py` - selection and cap tests.

## Steps

1. [x] In `state.py`, `read_mission_metadata(root, number)` returns
   `{area, depends_on, files}` from the index's front section (`Area:`,
   `Depends on:`) and its `## Files` bullet list, defaulting to empty values
   when absent. Backticked tokens in the Files list are kept only when they
   look like paths (a slash or a dot, no spaces, not an all-caps tag), so
   prose in a bullet is not mistaken for a file. Existing indexes without the
   metadata load unchanged; no planner is blocked from writing a mission for
   want of metadata.
2. [x] Add `src/ine_agent/compaction.py` with `write_snippet` (writes
   `.agent/compaction/<number>.md` - area, outcome, summary, changed files,
   verification, proposed follow-up and any finding, capped at 4000
   characters, rewritten in place so a retry leaves one snippet),
   `select_snippets` (newest-first, matched on the same declared area, an
   explicit `Depends on:`, or a changed file in common, capped at 3 snippets
   and 2000 characters, reading at most the newest 20 files), and `render`
   (the prompt block). An unreadable or hand-edited snippet is skipped, not
   guessed at; a mission that declares no relation is offered nothing.
3. [x] In `supervisor.py`, the run loop writes a snippet for every parsed
   receipt whatever its status - a blocked mission is exactly what a later
   mission in the same area most needs to know - and `impl_prompt` inserts
   the selection under a `PRIOR WORK IN THIS AREA` heading that frames it as a
   record rather than scope, or states plainly that there is none. The
   signals are read from the index itself via `_related_signals`.
4. [x] `CompactionTests` in `tests/test_ine_agent.py`: metadata optional and
   defaulted, metadata parsed from all three sources, a snippet holds the
   outcome and not the prompt, a snippet is bounded, selection by area /
   dependency / file, empty without a declared relation, never the mission's
   own snippet, the count and character caps, an unreadable snippet skipped,
   the prompt carrying a related snippet as data and in the right order, the
   "nothing related" wording, and a recorded (and a blocked) receipt leaving a
   snippet behind.

## Constraints

- Snippets are data, not instructions: they must never be able to change what
  the worker is asked to do.
- No unbounded directory walk of `.agent/` - read only the files the index
  names, and only the newest `max_snippets` candidates.
- No Ine language changes.

## Done when

- [x] `pytest tests/test_ine_agent.py` passes (260 passed).
- [x] A mission whose area matches a prior mission receives that mission's
  compact snippet and nothing else.
