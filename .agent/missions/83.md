## Goal

For kinds whose dictionary entry declares `narrow-class` + `narrow-layout`
in `defaults` while `layout` is `row` (today: card-group only), the HTML
backend emits ONE

    @media (max-width: 768px) { .<kind> { flex-direction: column; } }

in the document stylesheet. Gated entirely on the declared data of the
kind (card-group's `narrow-layout: "stack members"` + `narrow-class:
"viewport.width == narrow"`), never on the kind name. A program with no such
kind gains zero `@media` output — changing one declared value must not break
unrelated output (golden discipline).

Hint translation, documented in backend_html.py: `narrow-layout` "stack
members" maps to `flex-direction: column`; the `narrow-class` condition
expression is NOT evaluated (conditions/state UNDECIDED) — its presence
gates the rule, and the 768px breakpoint is the platform narrow fact in the
same class as the viewport meta (document-level, not vocabulary).
`flex:1` on members from the row layout is unchanged; in a column stack the
free space is zero (content-sized container) so members keep natural height.
