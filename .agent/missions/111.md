# Mission 111 — AI code generation integration research.

Goal: a NOTES proposal for dictionary-aware `.ine` generation from natural
language (prompt templates + a `.tmp/` prototype using an off-the-shelf
model interface), showing the current gaps and the safest integration point
— research + scratch prototype, no engine change.

Files:
  - .agent/NOTES.md           (append one section)
  - .tmp/ai-gen-probe/        (scratch prototype only)
  - src/ine/dictionary.py     (read only)
  - README.md (read only — the surface a generator should emit)

Steps:
  1. [ ] Read README's quick start and the dictionary surface (`suggest`,
          kinds, properties, members — the vocabulary a generator must stay
          inside). Write down the generation constraints: output must be a
          lexically-valid `.ine` that `analyze` accepts AND that uses only
          declared kinds/properties (VocabularyCoverageTests discipline).
  2. [ ] Design the prompt contract: a pinned system prompt that receives
          (goal sentence, the makeable kind list, per-kind allowed
          properties, containment rules) and must return ONLY an `.ine`
          program; plus a deterministic post-check (parse the reply with
          `ine.parser.parse(ine.lexer.lex(...))`; reject-and-retry once if
          invalid; if still invalid, fail with the parse error). Write the
          prompt + post-check into NOTES. Do not ship an API key or a
          command that requires one — no network call is wired in.
  3. [ ] Prototype in `.tmp/ai-gen-probe/probe.py`: the post-check is fully
          local (real parse+analyze of a canned generated program). For the
          model call itself, stub it — accept a pre-written "model reply"
          (a JSON file with a candidate program) so the harness is runnable
          offline and the local side is what is validated. Include 2 canned
          candidate programs (one valid, one syntactically broken) proving
          the checker accepts the good and rejects the bad with a useful
          error.
  4. [ ] Write NOTES `## Mission 111 — AI integration` with the prompt
          contract, the post-check rule, the probe evidence, the privacy/
          cost note (generation is an external service — no source ever
          leaves the machine unless the user opts in), and the safest
          integration point (an OPT-IN editor command behind a toggle, never
          implicit completion — the dictionary autocomplete stays local).
  5. [ ] Flag the commander decision: an AI integration is a product feature,
          not an implement-now default; the proposal ends with the opt-in
          design awaiting approval.

Verify: the probe's local checker accepts the good and rejects the broken
canned program; `git status` shows no src/ change.
Done when: NOTES has the prompt contract, post-check, probe evidence, opt-in
integration point, and the commander-gated endorsement note.
Do not: add an API key or network call; wire AI into autocomplete; invent
language syntax; import non-stdlib model libraries into the engine.
