# Mission 101 — Meta-programming investigation.

Goal: a NOTES proposal for a declarative template/expansion system ("make a
card for each …") with a `.tmp/` prototype showing source→N-expansion, kept
distinct from code generation — research only, no language change.

Files:
  - .agent/NOTES.md       (append one section)
  - .tmp/template-probe/  (scratch prototype only)
  - src/ine/parser.py, semantic.py   (read only)

Steps:
  1. [ ] Enumerate repeat-pattern needs and how they'd be written today
          (multiplicity via N handwritten cards; `make 3 card` if the parser
          supports it — verify against parser.py). Distinguish DECLARATIVE
          template expansion (a directive the engine expands into N concrete
          statements before analyze) from imperative code generation (a
          program that writes programs) — the proposal targets the former.
  2. [ ] Sketch the minimal template shape: a `template`/`for each`-style
          directive with a source variable and a list, whose bodies are plain
          statements with placeholders, expanded to N copies before semantic
          analysis (same AST-rewrite placement as item 99 — between parse and
          analyze). Define placeholders, the list source (inline literal
          today; no new runtime), and scoping (each expansion is an
          independent entity group).
  3. [ ] Prototype in `.tmp/template-probe/probe.py`: a `expand(source)`
          that turns ONE directive into N statements and re-emits source,
          then prove equivalence: `analyze(parse(lex(expanded)))` has N
          distinct entity ids vs. the 1 directive, with identical kinds and
          properties per member.
  4. [ ] Write NOTES `## Mission 101 — meta-programming` with the
          declarative-vs-codegen boundary, the directive sketch, the
          placeholder/scope rules, the equivalence evidence from the probe,
          and the recommendation naming what the commander must decide (any
          language-surface addition; `every` from item 99 may interact —
          cross-reference it).
  5. [ ] Explicitly flag the boundary: this expansion is NOT data display or
          runtime loops — it is author-time statement replication. State the
          non-goals (no user-defined functions, no conditional execution).

Verify: the probe's expansion output runs through the real pipeline green;
`git status` shows no src/ change.
Done when: NOTES carries the directive sketch, scope rules, probe evidence,
and the commander-gated recommendation.
Do not: add a template runtime; change the interpreter; invent language
surface without note of commander approval; write durable results into
`.tmp/`.
