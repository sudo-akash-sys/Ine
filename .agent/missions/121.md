# Mission 121 — named worker profiles, doctor, and resolved dry-run

Area: ine-agent
Depends on: 119
Goal: let the commander name the tool instead of editing code, resolve exactly
which command will run before it runs, and fail with a clear message when the
tool is missing or misconfigured.

## Why

`CliWorker` hard-codes the OpenCode invocation and reaches into
`opencode.db` for a model, so switching provider means editing Python. The
commander's OmniRoute bridge lives outside the repository and must stay there:
only the command shape belongs in the repo, never a key or a machine-specific
path.

## Files

- `src/ine_agent/profiles.py` (new) — profile schema, built-ins, resolution.
- `src/ine_agent/worker.py` — build a worker from a resolved profile.
- `src/ine_agent/cli.py` — `doctor`, `--dry-run`, `--max-missions` plumbing.
- `tests/test_ine_agent.py` — profile resolution and doctor tests.

## Steps

1. [x] `src/ine_agent/profiles.py` defines `WorkerProfile` with `name`,
   `command` (argv tokens), `prompt_transport` (`argument` or `stdin`),
   `model_args` (tokens carrying `{model}`), `timeout_seconds`, `env`
   (variable *names* only) and `env_var`. Built-ins `opencode` and `claude`
   reproduce today's argv exactly, with no model and no timeout.
2. [x] `.agent/workers.json` of shape `{"profiles": {...}}` adds or overrides
   a built-in, merged field by field, so a config that sets only `command`
   keeps the rest. `load_profiles` raises on a config it cannot read, cannot
   parse, or that holds an unknown field — a profile that was meant to be
   read and was not is a fact the commander is told, not a silent fallback to
   the built-in. `resolve` substitutes `{root}` and `{model}` (a closed

   non-list `command`, a bad transport, a non-numeric or negative timeout, an
   `env` entry that is not a bare variable name, and a `{model}` with no
   model given. No profile field can hold a credential: `env` takes names,
   and a value pasted in is refused by name.
3. [x] `build_worker(name, root, model=None)` returns a `ProfileWorker`; the
   supervisor still receives a one-argument factory (its default now closes
   over its own root), so nothing above the worker changed. `ProfileWorker`

   UTF-8 decode, and honours a profile `timeout_seconds` by killing the child
   and reporting a timeout by profile name.
4. [x] `ine-agent doctor` resolves a profile and reports the profile, the
   prompt transport, the model, the timeout, the exact argv, and any declared
   variable that is not set — resolving without constructing a worker and
   without spawning anything, exiting non-zero with a one-line remedy.
5. [x] `run --dry-run` prints the profile, the resolved command, the per-run
   budget, the next mission with its index state, and the number of further

6. [x] `ProfileTests`, `DoctorTests` and `DryRunReportTests` in
   `tests/test_ine_agent.py`: built-ins reproduce today's commands, root and
   model substitution, config override, unknown profile and every malformed
   field naming itself, a broken config failing loudly, credentials refused,
   the override seam and timeout through a real subprocess, doctor's
   resolved command / model / remedy / warning, and the dry-run's profile,
   command, budget, queue and absence of a run report.

## Finding

The index's "Why" claimed `CliWorker` "reaches into `opencode.db` for a
model". It does not: no model was ever placed on the command line, and the
`opencode.db` read lives in `usage.py`, which counts requests and tokens for
reporting. So `{model}` is a new capability rather than the removal of a
database dependency, and the built-in profiles deliberately keep today's
argv byte for byte so the change is not smuggled in as a behaviour change.
