# Mission 99 — Syntax sugar investigation.

Goal: a NOTES proposal for the highest-value syntactic sugar (`every`,
`with` blocks, shorthand forms) with a `.tmp/` AST-rewrite prototype proving
the pattern — research only, no language change.

Files:
  - .agent/NOTES.md            (append one section)
  - .tmp/sugar-probe/          (scratch prototype only)
  - src/ine/parser.py, semantic.py   (read only)
  - src/ine/lexer.py           (read only)

Steps:
  1. [ ] Map the current grammar surface from parser.py: statements (`make`,
          `say`, inside/group forms), possible multiplicity (`make 3 card`?
          verify against parser), property lines. Write down, for each
          candidate sugar, the exact expansion:
          - `every` — e.g. "make 3 card" shorthand spent in one statement
            (container of N children) and its desugaring to N child
            statements;
          - `with` blocks — a body of properties applied to one entity vs.
            the current `make` body — is this already `make <id>:`? state
            the overlap;
          - property shorthand — `card hello: "Title" then padding 32` vs.
            one-property-per-line the formatter (item 85) normalizes to.
          Verify each candidate is EXPRESSIBLE today (the "sugar" desugar
          must target a valid existing program).
  2. [ ] Prototype ONE sugar in `.tmp/sugar-probe/probe.py`: a
          source→source transformation `desugar(source) -> source` realized
          as lex→parse→rewrite-AST→re-emit-as-source (text re-emission only —
          the tree, not string patching) that a single corpus program then
          runs through the real pipeline to confirm equivalence:
          `analyze(parse(lex(source)))` entity counts equal
          `analyze(parse(lex(desugar(source))))` counts.
  3. [ ] Record in NOTES `## Mission 99 — syntax sugar proposal` the
          candidate table, the prototyped sugar's rule, the AST-rewrite-before-
          semantic design (rewrite step sits between parse and analyze; no
          lexer/interpreter change needed), the equivalence check result, and
          the recommendation (which candidate is worth a commander decision;
          `every`/shorthand vs. rejected forms).
  4. [ ] Explicitly flag that adopting any sugar is a LANGUAGE change —
          commander approval required (per AGENTS.md) — so the proposal ends
          with the decision question, not a "do it now" instruction.
  5. [ ] Keep the prototype in `.tmp/` (scratch); the proposal in NOTES is
          the durable output.

Verify: the probe's equivalence check runs green on the corpus program;
`git status` shows no src/ file modified.
Done when: NOTES has the candidate table, the desugaring rule, equivalence
evidence, and the commander-gated recommendation.
Do not: change lexer/parser/semantic/cli; add sugar to the language; invent
syntax; write durable results into `.tmp/`.
