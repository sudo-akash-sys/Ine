# Mission 105 — Plugin ecosystem investigation.

Goal: a NOTES proposal for a plugin system for backends / linters /
formatters (entry-point + manifest) with one prototyped custom-backend plugin
in `.tmp/` — research only; builds on, but does not implement, the Mission 79
backend contract.

Files:
  - .agent/NOTES.md          (append one section)
  - .tmp/plugin-probe/       (scratch prototype only)
  - src/ine/cli.py           (read only)
  - src/ine/backend_html.py, backend_c.py, backend_visual.py  (read only)

Steps:
  1. [ ] Re-read the Mission 79 NOTES result (`.agent/NOTES.md` `## Mission
          79 — backend plugin contract`): the `BackendError`/`Result`/
          `BACKENDS` registry contract, and its "did not decide" paragraph.
          State this plugin proposal as the NEXT step after 79, and record
          what adopting 79 first would simplify (single backend interface =
          plugin-shaped already).
  2. [ ] Design the plugin interface: a `manifest` (name, version,
          entry-point symbol, stage input it consumes: model or statements)
          and a discovery rule — either setuptools entry points
          (`[project.entry-points."ine.backend"] react = "app:render"`,
          flattenable via `importlib.metadata.entry_points`) or a
          filesystem convention (a `plugins/` dir scanned at CLI start).
          Compare both; recommend entry-points (no install-modification, no
          scan-order ambiguity) and record the security/sandbox trade-off
          (plugins are arbitrary code — a manifest documents intent, it does
          not sandbox; state that guardrails are a follow-up, not this
          mission).
  3. [ ] Prototype ONE custom backend plugin in `.tmp/plugin-probe/plug.py`
          that imports the real semantic model and renders a trivial
          JSON/text artifact (mirroring backend_html.render(model) -> str),
          plus a 6-line discoverer proving `entry_points` style lookup finds
          it. Run it against a real example program's model.
  4. [ ] Write NOTES `## Mission 105 — plugin ecosystem` with: the manifest
          schema, the discovery-mechanism recommendation (entry points) +
          why, what adopting Mission 79 removes, the security caveat, the
          prototype evidence, and the follow-up item list (linters/formatters
          via the same shape; a sandbox decision is commander territory).
  5. [ ] Do NOT modify cli.py or the backends — this is a design + probe.
          Flag that realizing the ecosystem is commander-approved architecture
          (it changes CLI public surface).

Verify: the probe's discoverer finds and runs the custom backend against the
example model; `git status` shows no src/ change.
Done when: NOTES has the manifest schema, discovery decision, security
caveat, and probe evidence, cross-linked to Mission 79.
Do not: register plugins in the real CLI; modify backends; implement
sandboxing; change the dictionary or language.
