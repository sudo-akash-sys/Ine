# Mission 97 — Example gallery expansion.

Goal: a structured gallery at `examples/gallery/` — basic, UI patterns, data
display, forms — each example a real `.ine` that builds, with rendered
outputs and README, backed by a test that every gallery example renders.

Files:
  - examples/gallery/README.md             (new: index, difficulty, build cmds)
  - examples/gallery/basic/                (new: say, single page)
  - examples/gallery/ui-patterns/          (new: header/footer, cards,
                                            navigation)
  - examples/gallery/data-display/         (new: dashboard-ish, metrics)
  - examples/gallery/forms/                (new: contact form)
  - examples/gallery/expected/             (new: rendered html)
  - tests/test_gallery.py                  (new)
  - existing examples/ (read only, do not move)

Steps:
  1. [ ] Survey existing examples (`hello`, `say`, `topbar`, `hero`, `cards`,
          `site`, `alice`, `native`) and choose which to re-house vs. leave
          untouched: do NOT move or rename existing example files (they are
          referenced by tests like `SiteExampleTests` and ReadmeQuickStart).
          The gallery adds NEW entries under its own directories.
  2. [ ] Write the gallery programs — each `.ine` must use only
          dictionary-covered kinds/properties (page, header, navigation,
          logo, container, card-group, card, button, banner, image, section,
          footer, title + universal properties, per VocabularyCoverageTests
          discipline): basic (a `say` greeting page, a single-entity page),
          ui-patterns (a header/footer page, a card-group with 2-3 cards
          using `layout: row`, a navigation+section page), data-display
          (metrics dashboards via `make number`-driven cards with
          `container` groups — use only declared value shapes `text`),
          forms (button/section layout WITHOUT `input`/`select`/`checkbox`
          — those field kinds are evidence-gated, see PLAN item 71; use
          declared kinds and note the boundary in the README).
  3. [ ] Build each example to `examples/gallery/expected/<name>.html` with
          the documented command (`python -m ine <file> -o
          gallery/expected/<name>.html`) and confirm the html renders non-empty.
  4. [ ] Add `tests/test_gallery.py` mirroring `SiteExampleTests`
          (test_ine.py:1568): discover all `.ine` under `examples/gallery/`,
          run the build pipeline in a temp dir, assert no error and non-empty
          HTML; additionally assert every gallery program's used kinds are
          all declared (the `for_model`/suggest surface).
  5. [ ] Write `examples/gallery/README.md`: table of examples grouped by
          difficulty (basic → advanced), the build command, what each
          demonstrates, and a note that forms are a vocabulary-boundary demo
          (field kinds tabled in PLAN item 71).

Verify: `python -m pytest tests/test_gallery.py -q` green; every gallery html
in `expected/` is non-empty and regenerable with the README command.
Done when: gallery README, 10+ real examples across the four groups, expected
outputs, and the render test land.
Do not: move/rename existing example files or break SiteExampleTests;
introduce undeclared vocabulary; add a lorem-ipsum placeholder.
