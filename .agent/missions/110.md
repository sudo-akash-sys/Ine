# Mission 110 — Release process documentation.

Goal: an executable release checklist (version bump → changelog → tag → wheel
→ install test → GitHub release) with a bump script, dry-run verified, and
the process written down.

Files:
  - RELEASE.md                    (new)
  - CHANGELOG.md                  (new — or adopt project conventions)
  - .agent/release/bump.py        (new — version-bump automation)
  - pyproject.toml                (read only)
  - .github/workflows/release.yml (new only if cheap and safe)

Steps:
  1. [ ] Read the current version homes: pyproject.toml `version = "0.1.0"`,
          and whether `src/ine/__init__.py` also carries a `__version__`
          (item 90 adds one — this mission must keep the two in sync).
          Write the release checklist in RELEASE.md in this exact order:
          (1) confirm `python -m pytest tests -q` green and goldens
          byte-identical; (2) bump version in pyproject.toml AND
          `__version__`; (3) add a CHANGELOG entry under the new tag; (4)
          `git tag v<version>`; (5) build the wheel
          (`python -m pip install build` then `python -m build`, or
          `python -m build --wheel`); (6) install the wheel into a THROWAWAY
          venv under `.tmp/` and smoke-test `ine --dict` lists 13 kinds
          (mirroring Mission 63's verified step) plus a hello build; (7)
          GitHub release with the wheel + changelog excerpt.
  2. [ ] Write `.agent/release/bump.py`: a stdin/stdout-free, single-arg
          script `python .agent/release/bump.py <major|minor|patch>` that
          reads pyproject.toml's version, increments semver, and updates BOTH
          version homes (pyproject `version` and `src/ine/__init__.py`
          `__version__` if present) in place, printing old → new. Guard it:
          it refuses to run when the worktree has uncommitted changes (a
          release must start clean) and refuses non-semver input.
  3. [ ] Dry-run the bump in a scratch checkout manner: run bump.py `patch`
          on a `.tmp/` COPY of pyproject.toml + __init__.py (never the real
          files — the worktree must stay clean), assert it returns the
          expected `0.1.0 → 0.1.1`. The dry-run means the SCRIPT logic is
          verified without mutating the repo.
  4. [ ] Add CHANGELOG.md with a `## Unreleased` section (or adopt whatever
          convention exists — check for one first). Do not fabricate
          historical entries beyond the current unreleased line.
  5. [ ] Add `.github/workflows/release.yml` ONLY if it can be made safe on
          first run (a `workflow_dispatch`-gated build+test job that builds
          the wheel and tests install in a fresh venv; do NOT auto-publish
          GH releases — publishing is a manual step until proven). If
          uncertain, omit the workflow and note the manual step in RELEASE.md.

Verify: bump.py's dry-run on the `.tmp` copy returns the expected old → new;
`python -m pytest tests -q` green with the repo untouched.
Done when: RELEASE.md checklist, CHANGELOG.md, and the dry-run-verified bump
script exist (workflow optional).
Do not: run the release for real (no tagging, no publishing, no wheel build
into the repo); change versions in the live repo.
