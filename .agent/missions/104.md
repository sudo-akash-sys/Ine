# Mission 104 — Community vocabulary repository investigation.

Goal: a NOTES proposal for community-contributed dictionary entries — format,
validation, namespacing, distribution — with a prototyped JSON package shape
in `.tmp/` — research only, no dictionary change.

Files:
  - .agent/NOTES.md       (append one section)
  - .tmp/community-vocab/ (scratch prototype only)
  - src/ine/dictionary.py (read only)
  - src/ine/dictionary/*.json (read only)

Steps:
  1. [ ] Read `dictionary.py`'s loading surface: how kind JSONs are found
          (`importlib.resources` + `__file__` fallback, per STATE.md),
          `makeable`, `find`, `properties_for`, `members`/`parents`,
          `suggest`, aliases, and the shape checked by the dictionary tests
          (DictionaryIntegrityTests, test_ine.py:569). Write down the exact
          fields a community entry must satisfy to be loadable and covered.
  2. [ ] Design the community-entry package format: a self-describing JSON
          (kind, `properties`, `members`, `contains`/parents, aliases,
          `meaning`, `value_shape`, a `"namespace"` field to avoid squatting
          like `vendor.cloud-hero`, and a `"version"`), under a specific
          directory convention (e.g. `dictionary/community/<namespace>/<kind>
          .json`). Sketch how `dictionary.py` would discover them without
          breaking the closed shipped set.
  3. [ ] Address quality control concretely in the proposal: mandatory fields,
          a validation script/py with the same checks as
          `DictionaryIntegrityTests` (kind names, member references resolve,
          no duplicate `inside` parents, value shapes valid), and a review
          gate (two community approvers or commander signoff for the
          `core` namespace; anything else is `community`).
  4. [ ] Prototype ONE packaged community entry in `.tmp/community-vocab/
          probe.json` and a mini loader that simulates how the future
          registry will read it — validate it against the same field checks
          the shipped JSONs pass. This is scratch evidence the format
          type-checks.
  5. [ ] Write NOTES `## Mission 104 — community vocabulary` with the format
          schema, discovery mechanism, validation rules, namespace policy,
          the probe result, and the distribution question (git repo? a
          registry endpoint? — state the trade-off and a recommendation;
          implementation is a follow-up PLAN item).

Verify: the probe entry passes the integrity checks copied from
DictionaryIntegrityTests; `git status` shows no src/ or dictionary change.
Done when: NOTES carries the schema, discovery, validation, namespace policy,
and the distribution recommendation with probe evidence.
Do not: add a community registry loader to dictionary.py; change shipped
JSONs; blur the core-vs-community boundary in the existing files.
