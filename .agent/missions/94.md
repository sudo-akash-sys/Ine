Goal: the golden-file discipline is reviewed and improved — the helpers are
easier to maintain, the when-to-update-goldens policy is written down, and
the four in-tree goldens stay byte-identical; an investigation with a
possible small helper change.

Files:
  - .agent/NOTES.md             (append one section)
  - tests/test_ine.py           (edit only if a helper change is chosen)
  - tests/expected/             (read only)

Steps:
  1. [ ] Read the current golden mechanism: `tests/expected/site.html` and
          how `SiteExampleTests` / `EndToEndTests` / HtmlStyleTests compare
          output (grep `expected/` and `byte-identical`). Note whether goldens
          are whole-file compares from in-tree examples or fixture strings.
  2. [ ] In NOTES `## Mission 94 — golden strategy`, write the plan:
          - Review of pytest-golden (or a tabled `--update-goldens` mark /
            env flag) as an option, with the concrete recommendation
            (whole-file compare against `tests/expected/` stays the norm —
            it is byte-identical discipline that the four goldens already
            follow; a `--update-goldens` env flag that REWRITES expected files
            only when set, so a deliberate change is one command, and is
            refused from CI).
          - The **when-to-update policy**: update a golden ONLY when the
            change to source/dictionary/backend is intentional; never update
            a golden to silence a regression; a golden diff on a normal run
            is a failing test. State that `hello`/`topbar` changed in Session
            42 (PLAN item 58) as the referent example of an approved update.
  3. [ ] Decide whether to add the small `--update-goldens` helper: an env
          variable `INE_UPDATE_GOLDENS=1` respected by the helper that loads
          expected files, writing the current output into `tests/expected/`
          when set; never consulted when unset. If added, update
          `tests/test_ine.py` helpers accordingly and add ONE test pinning
          that the env flag is refused in CI-like conditions (env unset) —
          no automatic golden writing on a normal run.
  4. [ ] If no code change is chosen, still record the policy exactly as
          above so the executor of any future change knows the rule.
  5. [ ] Re-run the full suite; the four goldens must be byte-identical (no
          modified expected files).

Verify: `python -m pytest tests -q` green; `git status` shows no change under
`tests/expected/` (or only the intended new helper/tests in test_ine.py).
Done when: NOTES carries the when-to-update policy and the tooling
recommendation; goldens are untouched.
Do not: update any golden to make a test pass; switch to an unproven golden
library; change in-tree example source.
