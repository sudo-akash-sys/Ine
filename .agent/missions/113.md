# Mission 113 — Accessibility audit.

Goal: the HTML backend's output is audited against WCAG 2.1 A/AA, gaps are
documented with proposed dictionary hints (`role`, `label`) and concrete
backend improvements — an audit whose output is the NOTES report; no source
changes unless a trivially safe, goldens-behavior-neutral fix merits one.

Files:
  - .agent/NOTES.md              (append one section)
  - src/ine/backend_html.py      (read only)
  - src/ine/dictionary/*.json    (read only)
  - tests/expected/*.html        (read only — the shipped goldens)

Steps:
  1. [ ] Build the real goldens (hello, topbar, hero, cards — 
          `tests/expected/`) and read `backend_html.py` sections: `_attrs`
          (:126), `_stylesheet` (:95), `_render_engine`/render (:56),
          `_render_children` (:159). Audit each emitted element against:
          - **semantic HTML**: is `header`, `nav`, `main`, `footer`,
            `section` used for the corresponding kinds? (kind → tag map).
          - **heading structure**: one `h1` per page, no skipped levels.
          - **labels/keyboard**: interactive-ish elements (button) keyboard-
            operable; images need `alt` (what does `image` emit today?).
          - **color contrast**: `KIND_COLORS`/dictionary colors vs. page
            background — flag any near-identical pair.
          - **ARIA**: where a role would compensate a visual-only affordance.
  2. [ ] Record in NOTES `## Mission 113 — accessibility audit` a per-golden
          table (criterion | current | gap | fix) and rank the fixes by
          cheapness: dictionary hints (`role`, `label`, `alt` — additive
          JSON fields read by backend_html; goldens WILL change → flag that
          as an approved-update per the item 94 policy); backend-only
          default changes (heading hierarchy, `alt=""` for decorative
          images); nothing that renames kinds.
  3. [ ] If a fix is trivially safe AND behavior-neutral (e.g. adding an
          `alt` attribute default that only appears when the dictionary has
          no value — so goldens stay byte-identical), implement it with a
          unit test pinning the new attribute when applicable; otherwise list
          the fix as a follow-up PLAN item — the audit does not rewrite the
          backends on spec.
  4. [ ] Cross-reference the Mission 78 findings (`position: bottom`
          footer bug, style-block consumption) where they touch accessibility
          (a footer pinned bottom is fine; an unstyled sibling may violate
          reading order).
  5. [ ] Conclude with the recommendation: adopt the `role`/`label`/`alt`
          dictionary hints as the first concrete step (commander signoff on
          the dictionary schema addition — it is a schema change), and name
          the follow-up mission that implements them.

Verify: `python -m pytest tests -q` green; goldens byte-identical (no
unapproved HTML change).
Done when: NOTES carries the per-criterion audit table, ranked fixes, and the
recommended first step with its commander signoff point.
Do not: change backend_html.py or dictionary JSON in a way that moves a
golden without an approved-update note; rename kinds; add ARIA blindly.
