# Mission 95 — Tutorial series creation.

Goal: four real, buildable tutorials in `docs/tutorials/` — a first program,
the dictionary, the editor, a card layout — each with exercises that have
model answers, backed by a test that every tutorial program builds.

Files:
  - docs/tutorials/01-first-program.md     (new)
  - docs/tutorials/02-understanding-the-dictionary.md  (new)
  - docs/tutorials/03-using-the-editor.md  (new)
  - docs/tutorials/04-card-layout.md       (new)
  - docs/tutorials/solutions/              (new: model answers)
  - docs/tutorials/README.md               (new: index + prerequisites)
  - tests/test_tutorials.py                (new)

Steps:
  1. [ ] Write the four tutorials as markdown with the documented commands
          exactly as README.md quick-start documents them
          (`python -m ine <file>.ine -o <out>.html`, `ine --dict <kind>`):
          (1) First Ine program — `say`, `make page`, build to HTML, the
              5-stage pipeline in words without jargon; (2) The dictionary —
          `ine --dict`, kinds/members/properties, `meaning` in the JSON,
          aliases;  (3) Using the editor — `editor/vscode-ine`, install+open,
          the completion contexts, validate diagnostics advisory note; (4) A
          card layout — `make card-group:` with 2-3 `card`s, `inside:`,
          `layout: row`, and a `footer`, building to HTML. Each ends with
          2-3 exercises whose full programs live under `solutions/`.
  2. [ ] Put every `.ine` sample in the tutorials' `solutions/` directory
          (or a shared `samples/`) so each is a real file, not a markdown
          snippet that can drift.
  3. [ ] Add `tests/test_tutorials.py`: discover every `.ine` under
          `docs/tutorials/solutions/`, build each with `ine.cli.build` (or
          the resolve/execute pipeline) in a temp dir, and assert it raises
          no Lex/Syntax/Semantic error and produces a non-empty HTML string
          for page-describing programs. Follow the existing `SiteExampleTests`
          pattern (test_ine.py:1568).
  4. [ ] Cross-link `docs/tutorials/README.md` from the main README's
          "learn Ine" area if a natural spot exists (a one-line addition);
          otherwise leave README untouched and note the link point.
  5. [ ] Use real programs only — no lorem ipsum; every sample must build and
          be dictionary-covered (`VocabularyCoverageTests` spirit) so a
          tutorial never teaches an undeclared construct.

Verify: `python -m pytest tests/test_tutorials.py -q` green; the tutorials'
commands reproduce in a fresh shell (quick-start flow passes).
Done when: four tutorials + solutions + README land, and every tutorial
program builds.
Do not: invent syntax the engine does not support; copy README boilerplate
verbatim; change the engine or dictionary.
