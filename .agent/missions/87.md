# Mission 87 — Editor testing infrastructure.

Goal: the VS Code extension has a real test harness (VS Code Extension Test
Runner) with integration tests covering completion, diagnostics and
formatting, runnable locally and in CI, separate from the Python test suite.

Files:
  - editor/vscode-ine/package.json       (edit: test scripts + devDeps)
  - editor/vscode-ine/test/run-tests.js  (new)
  - editor/vscode-ine/test/suite/...     (new: integration tests)
  - .github/workflows/editor-tests.yml   (new)
  - editor/vscode-ine/README.md          (edit: how to run tests)

Steps:
  1. [ ] Add the VS Code test-runner scaffolding to the extension: a
          `test/run-tests.js` launcher (`@vscode/test-electron`) that
          downloads an appropriate VS Code build and runs the extension
          tests headed against a workspace fixture; wire `npm test` /
          `npm run test` scripts and the `devDependencies` +
          `test` activation in package.json. Use the standard
          `vscode-test` pattern (download, runTests with extension
          development path).
  2. [ ] Create a small workspace fixture (`.ine` file exercising `make`,
          properties, `inside:` containment) under `editor/vscode-ine/test/
          fixture/` and have the runner open it in the test instance.
  3. [ ] Write integration tests in `test/suite/` that activate the extension
          and assert: completion items are returned for a `make ` cursor
          position (DocumentSelector `ine`); a broken buffer surfaces a
          diagnostic (red error) after the validate query; a `format`
          request returns `text` via a DocumentFormattingEditProvider that
          the editor can apply; hover on a known kind returns the dictionary
          `meaning`. Prefer asserting on the providers/commands directly
          (await the provider functions) so the tests stay deterministic
          without UI timing.
  4. [ ] Add `.github/workflows/editor-tests.yml` running `npm ci && npm
          test` in the extension directory on push/PR (separate job from the
          main Python suite; pinned node version; extension tests are
          headed — use `xvfb-run` on Linux).
  5. [ ] Document in `editor/vscode-ine/README.md` how to run the tests
          locally (npm install / npm test) and what the fixture covers.
  6. [ ] Ensure the extension still activates by `onLanguage:ine` only, and
          that the new package.json fields are valid JSON matching npm's
          expectations (no stray opencode/ine keys).

Verify: locally `npm test` (or `node test/run-tests.js`) passes with the test
instance; `python -m pytest tests -q` still green; CI workflow file parses.
Done when: `npm test` in `editor/vscode-ine` runs the suite green, and CI has
a separate editor job.
Do not: alter extension.js behavior beyond what the integration tests
exercise; commit a heavy fixture; change the Python test suite layout.
