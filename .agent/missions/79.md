# Mission 79 — Backend plugin architecture investigation

Goal: a written interface contract that lets a new backend (React, Flutter, …)
be added without editing the CLI or the semantic layer, plus the exact list of
places that currently violate it — recorded in `.agent/NOTES.md`. No source
file changes.

Files:
  - .agent/NOTES.md             (append one section)
  - src/ine/cli.py              (read only)
  - src/ine/backend_html.py     (read only)
  - src/ine/backend_visual.py   (read only)
  - src/ine/backend_c.py        (read only)
  - src/ine/native.py           (read only)

Steps:
  1. [x] Read `src/ine/cli.py`: `main` (:48), `_html` (:91), `_native` (:110),
          `_visual` (:133). Write down the exact five-stage pipeline each of
          them repeats (`lex` → `parse` → `analyze` → `resolve` → `execute`)
          and the line where they diverge.
  2. [x] Establish, and write down, the asymmetry that blocks a uniform
          contract: `backend_html.render` takes the **model** (built from
          `analyze`), `backend_visual.render`/`show` takes the **model**, but
          `backend_c.emit` takes the **statements** (the output of `resolve`,
          called from `native.py:36`). Name which stage each backend
          actually consumes.
  3. [x] Read `backend_html.render` (:56) and `backend_visual.render` (:100)
          and list every argument either one takes beyond the model
          (`title_override`) and every return value (`str` vs a live
          `tk.Tk`). Record whether a backend can currently signal failure —
          `BackendError` (:35) and `VisualError` (:257) are two unrelated
          exception types with no shared base.
  4. [x] Write the proposed contract as a short code block in the NOTES
          section: one `render(stage_input) -> Result` entry point per
          backend, a single `BackendError` base, and a registry mapping a
          backend name to its entry point, with the CLI reduced to selecting
          from the registry. Keep it to the minimum that removes the
          asymmetry of step 2 — do not design an ecosystem.
  5. [x] Against that contract, list every concrete edit a new backend would
          need today (`cli.py` arg parsing, a new import, a new `_stage`
          function, a new error class) and mark each as "removed by the
          contract" or "still required". That list is the proposal's
          evidence.
  6. [x] APPEND a section to `.agent/NOTES.md` titled
          `## Mission 79 — backend plugin contract` with, in order: the
          five-stage pipeline from step 1; the consumption asymmetry and the
          exception-type split from steps 2–3; the proposed contract from
          step 4; the edit-cost list from step 5; and one paragraph on what
          the mission did NOT decide (whether the contract is worth its
          migration cost — the commander's call, since it touches
          `cli.py`'s public flags).
  7. [x] Optionally prototype the registry in `.tmp/` as scratch to check the
          shape compiles. If you do, say so in the section, and keep the
          prototype out of `src/` — `.tmp/` is scratch and must not be cited
          as the location of a durable result.

Verify: `python -m pytest tests -q` — all pass, and `git status` shows no
modified source file (this mission edits nothing but NOTES.md).
Done when: NOTES.md carries all five parts of step 6, and the "did not
decide" paragraph names the commander's decision explicitly.
Do not: refactor `cli.py` or any backend; add a plugin loader; change
Ine's syntax or dictionary schema; write outside the repository.
