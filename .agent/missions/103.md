# Mission 103 — Contributor onboarding improvement.

Goal: a complete `CONTRIBUTING_GUIDE.md` (repo setup, tests, changes, PR
process, review standards) plus GitHub issue/PR templates, linked from
CONTRIBUTING.md, that gets a new contributor to a green suite in minutes.

Files:
  - CONTRIBUTING_GUIDE.md               (new)
  - .github/ISSUE_TEMPLATE/bug_report.md    (new)
  - .github/ISSUE_TEMPLATE/feature_request.md (new)
  - .github/PULL_REQUEST_TEMPLATE.md        (new)
  - CONTRIBUTING.md                      (edit: link to the guide)
  - README.md (read only — commands the guide quotes must match)

Steps:
  1. [ ] Extract the real, verified ways-to-run from the repo: quick start
          from README (`python -m ine hello.ine -o hello.html`,
          `ine --dict <kind>`), the test command actually in use
          (`python -m pytest tests -q` from the repo root), the editor setup
          (`editor/vscode-ine`, `npm install`, F5 / Run Extension), and the
          agent tooling (`python src/ine_agent/cli.py run --dry-run`).
          Reproduce the suite command ONCE and record the exact invocation and
          expected count/exit in the guide so a green check is unambiguous.
  2. [ ] Write `CONTRIBUTING_GUIDE.md` in this order: repo overview (.agent/
          rules, the Ine constraints from AGENTS.md), environment setup
          (Python 3.10+, Node for the extension, Windows treatment), building
          & running the suite (exact commands + a note that the tkinter
          suite may skip headless — see Session 48), making a change
          (conventions: no comments unless asked, follow existing patterns,
          run focused tests), the PR process (branch, lint/typecheck if
          configured, one focused test pass, full suite at the end), and
          review standards (dictionary coverage, goldens byte-identical, no
          language-surface change without commander approval).
  3. [ ] Add the three GitHub templates: bug report (environment, command,
          expected vs actual, repro file), feature request (problem, proposed
          surface, dictionary/CLI/editor scope, commander-signoff note), PR
          (what, evidence, tests run, goldens touched?, commander-gate
          checkbox for language changes).
  4. [ ] Link `CONTRIBUTING_GUIDE.md` from `CONTRIBUTING.md` (a short
          "getting started → see the guide" pointer). Do not rewrite
          CONTRIBUTING.md wholesale; keep any existing local conventions it
          already documents.
  5. [ ] Verify the guide's quoted commands are real by re-running the two
          central ones (pytest on tests, and the README quick start path).

Verify: `python -m pytest tests -q` green; the guide's quick-start commands
reproduce; templates are valid GitHub front-matter markdown.
Done when: the guide exists and is linked from CONTRIBUTING.md, templates
land under .github/, and every command in the guide has been run once.
Do not: invent commands that do not work; restructure the repo; add CI (item
87 owns the editor CI; a core CI is a separate, unplanned item).
