# Mission 85 — Formatter implementation.

Goal: a deterministic `ine format`-style canonical formatter for `.ine` source
(the language has a small closed grammar, so formatting is a parse-to-text
re-emit) exposed through the editor as a document formatter, with the language
surface and semantics untouched.

Files:
  - src/ine/formatter.py         (new)
  - tests/test_formatter.py      (new)
  - src/ine/__init__.py          (edit, export `format_program`)
  - editor/vscode-ine/extension.js  (edit: formatting provider + command)

Steps:
  1. [ ] Write `src/ine/formatter.py` with `format_program(source: str) -> str`
          implemented as: `tokens = lex(source)`, `statements = parse(tokens)`,
          then emit canonical text from the statement structure (deterministic
          rules: one `make <kind> <id>:` per line; body properties indented by
          4 spaces; one property per line ` <name> <value>`; `inside:` /
          collection statements on their own lines; a blank line between
          top-level statement groups; trailing single newline, no trailing
          spaces). Unparseable source returns `source` unchanged (formatting
          must never destroy a file, including a syntax-broken one). All
          emission derives from the parsed statements, never from raw text
          line matching.
  2. [ ] Add `format_program`, `FormatterError` (or reuse `SyntaxError` for
          the do-not-touch path) to `src/ine/__init__.py` exports.
  3. [ ] Add `tests/test_formatter.py`: formatting `format_program(x)` is
          idempotent (`format(format(x)) == format(x)`); a hand-written
          canonical sample (multi-line `make card:` with properties, an
          `inside:` child, a `say` line) formats byte-exactly; a syntax-broken
          buffer round-trips unchanged; formatting never alters the parse tree
          (assert `parse(lex(format(x)))` statements equal `parse(lex(x))` for
          the valid samples — normalization must not change meaning).
  4. [ ] Expose formatting to the editor **without** adding new text fields to
          `autocomplete.py` unless needed: add a `{"format": true, "buffer"}`
          query in `autocomplete.py::complete` returning
          `{"format": True, "text": <formatted>}` (guarded, `id` echoed), and
          in `extension.js` register a `DocumentFormattingEditProvider` for
          `ine` plus a `ene.format` command that formats the active document;
          add the command + `formatOnSave` (`"editor.formatOnSave": true` for
          `[ine]`) to `package.json`.
  5. [ ] Keep package.json's `contributes.commands` block; do not restructure
          the extension (item 87 owns testing infrastructure).

Verify: `python -m pytest tests/test_formatter.py tests/test_autocomplete.py -q`
— all pass; a live `{"format": true}` query formats a sample buffer.
Done when: formatting is deterministic (idempotent), meaning-preserving, and
the editor can format the active document on save or by command.
Do not: change lexer/parser/interpreter semantics; reformat files on import;
touch `cli.py` (item 90 owns CLI ergonomics) unless `ine format` is approved
by the commander; write outside the repo.
