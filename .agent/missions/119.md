# Mission 119 — lean one-mission handoff and structured receipt

Area: ine-agent
Goal: replace the repeated control-plane prompt injection with a small fixed
execution contract, and replace model-driven recording with a machine-readable
receipt that Python records deterministically.

## Why

`impl_prompt()` currently embeds `.agent/WORKER_PROMPT.md`, `.agent/MISSION.md`,
the distilled state, plan state, history, and usage. That bundle is re-sent on
every cycle even though the worker only needs the one mission index it was
given, and the snapshot can be stale by the time it arrives. The worker is also
asked to rewrite STATE, HISTORY, PLAN, and RUN_REPORTS by hand, which is both
expensive and unverified.

## Files

- `src/ine_agent/receipt.py` (new) — receipt dataclass, parse and render.
- `src/ine_agent/supervisor.py` — prompt construction and receipt handling.
- `src/ine_agent/state.py` — deterministic plan/history/state/notes recording.
- `tests/test_ine_agent.py` — prompt, receipt, and recording tests.

## Steps

1. [x] Add `src/ine_agent/receipt.py` with a `Receipt` dataclass and
   `parse_receipt(text)`. The worker emits, as the last thing in its final
   message, a fenced block introduced by the exact line
   `INE_RECEIPT_JSON` containing one JSON object with keys `status`, `summary`,
   `changed_files` (list of paths), `verification` (list of strings), and
   optional `area`, `finding` and `follow_up`. `status` is one of `done`,
   `needs_commander`, `missing_prerequisite`, `failed`. Parsing takes the last
   marker, decodes one JSON object, and returns `None` when absent, malformed,
   or of unknown status. The marker text, the field meanings and the example
   all live in one module-level `contract()` so prompt and parser cannot
   drift. (`finding` was added during execution: NOTES.md is written only
   when a receipt carries a durable fact, and a receipt needs a field to say
   so.)
2. [x] In `supervisor.py`, build the implementation prompt from a fixed contract
   plus the mission index only. The contract states: execute the mission in
   order, do not re-plan, do not edit `.agent/` control-plane files, do not
   spawn subagents or use the network, run focused tests before finishing,
   print a short human summary and then the receipt block, and end the turn
   there. Removed `_mission_block()`, `_distill_state()`, and the embedding of
   `WORKER_PROMPT.md`, `MISSION.md`, `STATE.md`, `HISTORY.md`, `PLAN.md`, and
   usage from the implementation prompt. `diagnosis_prompt()` and
   `review_prompt()` are untouched — the diagnosis call is removed in mission
   123. The `CLASSIFICATION:`/`REASON:` block is no longer asked for; the
   parser survives as a compatibility fallback and `_diagnose` now reads the
   receipt first (`Source.RECEIPT`).
3. [x] In `state.py`, add `record_mission_outcome(root, task, receipt, status,
   session=None)`. It, idempotently: rewrites the plan item's tag to `DONE`
   via the new `mark_done()` when status is `done`; appends a dated
   `## Session N - ine-agent mission <n>` block to `HISTORY.md` with the
   summary, changed files and verification; rewrites only the `Current focus`
   and `Health` sections of `STATE.md` to a short generated position,
   preserving every other line; appends a bounded `## Mission N` section to
   `NOTES.md` only when the receipt carries a `finding`; and never rewrites
   `HISTORY.md` or `NOTES.md` wholesale. `next_session_number()` derives the
   session from HISTORY.md so the two never desynchronise. The existing tag
   parser and index loading are untouched.
4. [x] In `supervisor.py`, `_outcome` takes the receipt: a `done` receipt with
   exit code 0 is completion on its own, so a worker that leaves PLAN.md
   alone is still recorded. The `done` branch calls `_record_receipt`, which
   records through the state module and writes the receipt into the run
   report; a cycle that finished without a receipt says so in the report
   rather than being silently recorded. A non-`done` receipt feeds
   `_diagnosis_outcome` so the reason costs no second call.
5. [x] Tests updated and added in `tests/test_ine_agent.py`:
   `ReceiptTests` (well-formed, optional fields, prose ignored, last marker
   wins, a marker inside a line is not a marker, seven unreadable shapes are
   `None`, fields bounded, non-string list entries dropped, the contract's own
   example parses), `DeterministicRecordingTests` (plan tag, history, notes and
   state head; twice-run does not duplicate; non-done records nothing; NOTES
   untouched without a finding; STATE head rewritten and the rest preserved; a
   STATE without head sections is not rewritten; the session number follows
   HISTORY; `mark_done` idempotent), and rewritten `MissionTests` /
   `PromptContractTests` asserting the prompt carries the mission and the
   receipt contract and none of the control-plane bodies — including a test
   that the prompt is byte-identical in a repository with 4000-line records
   and one with empty ones.
   `PlanHygieneTests.test_items_numbered_sequentially_without_gaps` became
   `test_item_numbers_are_unique` plus
   `test_item_numbers_ascend_within_each_section`: the priority section
   inserted above the standing product work takes the next free numbers
   (119-125 before 84-118), which uniqueness and per-section ascent still
   pin, while "no gaps anywhere" only encoded the old layout.


## Constraints

  advances.
- No second model call in this mission.
