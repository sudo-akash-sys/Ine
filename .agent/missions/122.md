# Mission 122 — bounded OpenCode execution profile

Area: ine-agent
Depends on: 121
Goal: give the OpenCode worker a project-local agent definition that is a
coding agent, not a research agent, and that cannot run away.

## Why

`--pure` does not prevent the worker from reading project rules, spawning
subagents, or searching the web, and an unbounded step budget is how a single
mission turns into a long request chain. The cost is control of the agent
definition, not of the model.

## Files

- `.opencode/agents/ine-worker.md` (new) — the agent definition.
- `src/ine_agent/profiles.py` — the built-in `opencode` profile selects it.
- `tests/test_ine_agent.py` — profile/agent consistency test.

## Steps

1. [x] `.opencode/agents/ine-worker.md`, front matter `description`,
   `mode: primary`, `temperature: 0.1`, `steps: 60`, and an explicit
   `permission` map: `read`/`glob`/`grep`/`list`/`edit`/`bash` `allow`;
   `external_directory`, `task`, `question`, `webfetch`, `websearch`,
   `skill`, `doom_loop` and `todowrite` `deny`. No `model` key, and no
   deprecated `maxSteps`; the permission map is exhaustive because
   anything unlisted is allowed by default.
2. [x] The body is 25 lines: one mission index, carried out in order; no
   re-planning; read the minimum; stay in the Files list; focused tests then
   one full suite; never edit `.agent/`; the guardrails; end with the
   receipt block from mission 119 and nothing after it.
3. [x] The built-in `opencode` profile passes `--agent ine-worker` and
   declares `model_args: ["--model", "{model}"]`, so model selection is
   profile data. No repository `opencode.json` was added: `.opencode/agents/`
   is discovered on its own.
4. [x] `WorkerAgentDefinitionTests` in `tests/test_ine_agent.py`: the file
   is where OpenCode looks and its name is the agent name; the front matter
   declares a bounded primary agent with a required description and no
   `model`/`maxSteps`; every denied and allowed tool is named; the
   permission set is exactly the expected set, so a missing tool is a hole
   rather than a neutral; the body is under 40 lines and says the load-bearing
   things; the built-in profile selects this agent by name.

## Finding

- The index's Done-when says `ine-agent doctor --profile opencode`. The flag
  mission 121 shipped is `--worker <name>`, which is what `doctor` takes. The
  profile *is* named `opencode`; only the flag word differs.
- OpenCode ignores a malformed agent file silently, so "no step budget and no
  denials" is indistinguishable from success on the loop's side. That is why
  the permission set is asserted to be exhaustive rather than spot-checked.
- `todowrite` is denied, which the index did not list either way. A todo list
  would restate the mission index the worker was given, and the index is the
  whole scope.

## Constraints

- Consult the OpenCode agent front-matter schema before writing the file and
  follow it exactly; a malformed file is silently ignored.
- No Ine language changes, and no change to the mission contract from
  mission 119.

## Done when

- [x] The file parses as an OpenCode agent (front matter verified against the
  published schema and with a real YAML parse) and `ine-agent doctor --worker
  opencode` resolves the command that selects it.
