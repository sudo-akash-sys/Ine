3. [x] Pilot the new flow end to end against a stub worker over a small queue:

6. [x] Tag every plan item this refactor touched with exactly one of

## Findings

- **The pilot found what the unit tests could not.** Every tally defect in
  mission 124 needed a run with a *failed* mission and a *gated* mission at
  the same time: alone, a gated mission looked right, and a failed mission
  looked like it was counted once. A contract assembled from single-outcome
  tests is not yet a contract.
- **A stub cannot measure model requests, and the note says so.** The pilot
  runs in 0.24 s and spends zero requests; presenting any request count from it
  as the run's cost would repeat exactly the mistake mission 123 fixed. The
  measured half of the comparison (prompt size) is real; the request half is
  cited from mission 115 and from the structural change (the diagnosis call
  no longer exists).
- **`CLAUDE_REVIEW` is the documented example of a tag that does not mean what
  it looks like**, which is why CONTRIBUTING.md says a follow-up is "proposed,
  never executed" and DECISIONS.md records the marker next to the tag.
