# Mission 107 — Code quality audit.

Goal: static analysis (mypy / pyflakes-style / bandit) is run against
`src/ine`, actual issues are fixed or documented, and a quality-check
config + command exists — with the suite staying green and behavior
unchanged.

Files:
  - pyproject.toml          (edit: add a `[tool.ruff]`/mypy section if adopted;
                             add optional dev dependency)
  - src/ine/**              (edit only for real issues found)
  - .agent/NOTES.md         (append the audit report)

Steps:
  1. [ ] Run a lightweight trio on `src/ine` from the repo root and record
          each tool's verdict:
          - `python -m compileall` / a `py_compile` pass (always available)
            to catch syntax/import mistakes;
          - `python -m pip list | findstr /i "mypy ruff bandit pylint"` to see
            what is installed (an offline env has none — that is a finding,
            not a failure);
          - if `ruff` is installed: `python -m ruff check src/ine`; if `mypy`
            is installed: `python -m mypy src/ine`; if `bandit`: `python -m
            bandit -r src/ine -q`. In .agent/NOTES record exactly which tools
            ran and their counts.
  2. [ ] From what actually ran, list concrete findings grouped
          critical/minor/style. Fix ONLY genuine defects (an unused import, a
          bare `except`, a potential `os.path` portability slip, incorrect
          exception chaining) — behavior-preserving edits. Do NOT churn style
          (rename all variables, add type annotations everywhere) — that is
          scope creep for an audit.
  3. [ ] If ruff/mypy is present, add the config section to pyproject.toml
          (`[tool.ruff]` with a line-length + select set that passes on the
          codebase, or `[tool.mypy]` settings you verified) and record the
          exact command to re-run. Add the tool as an optional dev extra
          (`[project.optional-dependencies] dev = ["ruff", "mypy"]`) if a
          dev extra exists or needs creating.
  4. [ ] Add a `tests/test_quality.py` ONLY if it can run offline without the
          tools failing (e.g. always-available compileall success over src/ —
          never make the main suite depend on an absent tool; skip cleanly
          when a tool is missing).
  5. [ ] Write the audit report in NOTES `## Mission 107 — code quality
          audit`: tools run, counts, issues fixed, issues deliberately left
          (with reason), the config/command added, and the projected targets
          (type coverage, complexity) for a future full lint pass.

Verify: `python -m pytest tests -q` green after any edits; the configured
tool command (if a tool is present) passes on `src/ine`.
Done when: NOTES carries the audit, genuine issues are fixed, and the
quality-check config + command are documented.
Do not: add CI (no CI exists for core; that is unplanned); make the suite
depend on an uninstalled tool; mass-rewrite code style.
