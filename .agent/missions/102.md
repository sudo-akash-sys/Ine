# Mission 102 — Language versioning strategy.

Goal: a NOTES version-policy document — semver for .ine programs?, a
`# ine-version` file marker, compatibility-break and migration policy —
research only, no code.

Files:
  - .agent/NOTES.md      (append one section)
  - LANGUAGE.md          (read only)
  - pyproject.toml       (read only, ine package version = 0.1.0)
  - WORKBOOK.md          (read only)

Steps:
  1. [ ] Read LANGUAGE.md's spec stance and WORKBOOK's decisions on stability
          (does anything already promise backward compatibility? look for
          "break", "freeze", "compat"). Read the current version marker
          situation: pyproject.toml `version = "0.1.0"`; is there any
          in-language version declaration today (grep the lexer for
          `version`/`#` handling)?
  2. [ ] Decide, and write down, the recommended policy:
          - whether language and package version move in lockstep (keep both
            at 0.1 equiv while 0.x — YES, simplest, they are the same repo);
          - a `# ine-version: <semver>` marker as the file-level declaration:
            the marker is advisory (a comment line the lexer already ignores
            — verify it won't collide with `say` or property parsing), a
            program WITHOUT a marker is assumed the running version; a
            program WITH a newer marker prints a warning, never a hard fail.
          - the compatibility rule: 0.x may break syntax/semantics, but every
            breaking change ships a migration note + the failing feature is
            recorded in LANGUAGE.md's change log section (add one if absent).
  3. [ ] Write NOTES `## Mission 102 — versioning strategy` with: the
          lockstep decision, the marker syntax and lenient enforcement, the
          major/minor/patch mapping to language-level changes (patch = bugfix
          with no surface change; minor = additive dictionary/editor feature;
          major = syntax/semantic break), and the migration checklist
          (change log entry, migration guide, PLAN cross-ref). Reference the
          Session 42 HTML-styling change that already "moved" goldens as the
          precedent for what a minor-with-golden-update looks like.
  4. [ ] End with the commander-gated decision question (adopting the marker
          touches the language surface if it is more than a comment).

Verify: `git status` shows no src/ change; the marker-as-comment claim is
checked against the lexer.
Done when: NOTES has the policy, lockstep decision, marker rules, and
documented migration checklist.
Do not: implement the marker; change the lexer; bump any version.
